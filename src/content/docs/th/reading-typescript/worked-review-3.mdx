interface UserRecord { id: number; name: string }

class DataCache<T> {
  private store: Record<string, any> = {}; // BUG 1: any -- the cache's own storage loses precision immediately
  set(key: string, value: T): void {
    this.store[key] = value;
  }
  get(key: string): T | undefined {
    return this.store[key];
  }
}

class Animal { speak(): string { return "..."; } }
class Dog extends Animal { bark(): string { return "woof"; } }
class Cat extends Animal { speak(): string { return "meow"; } }

function seedWithCat(cache: DataCache<Animal>): void {
  cache.set("pet", new Cat());
}

const dogCache = new DataCache<Dog>();
dogCache.set("pet", new Dog());
seedWithCat(dogCache); // BUG 2: variance -- DataCache<Dog> accepted where DataCache<Animal> is expected

interface Repository<T> {
  findById(id: number): T | undefined;
}

class UserCacheRepository implements Repository<UserRecord> { // BUG 3: single implementer, generic used once
  private cache = new DataCache<UserRecord>();
  save(id: number, record: UserRecord): void {
    this.cache.set(String(id), record);
  }
  findById(id: number): UserRecord | undefined {
    return this.cache.get(String(id));
  }
}

async function persistToRemote(entry: UserRecord): Promise<void> {
  await new Promise<void>((resolve) => setTimeout(resolve, 5));
  console.log("persisted:", entry.name);
}

function cacheAndPersist(repo: UserCacheRepository, entry: UserRecord): void {
  repo.save(entry.id, entry);
  persistToRemote(entry); // BUG 4: floating promise -- never awaited
}

const repo = new UserCacheRepository();
cacheAndPersist(repo, { id: 1, name: "Ada" });
console.log(repo.findById(1));

const pet = dogCache.get("pet");
console.log(pet?.bark()); // pet is actually a Cat now -- crashes
`.trim();

## ลองหา bug ก่อนอ่านต่อ

สองในนี้เป็น generics-specific ในแบบที่รีวิวก่อน ๆ ไม่มี ลองบอกให้ครบทั้งสี่ก่อนเปิดเฉลย

<details>
<summary>Bug 1 — บรรทัด 4, `private store: Record<string, any>`</summary>

**Symptom:** public API ของ `DataCache<T>` (`set(key, value: T)`, `get(key): T | undefined`) แม่นยำสมบูรณ์ — แต่ storage *ภายใน* ของมันยอมแพ้กับ `T` ไปเลย type ค่าที่เก็บทุกตัวเป็น `any`

**Evidence:** ไม่มีอะไร crash จากบรรทัดนี้อย่างเดียวในโปรแกรมนี้ แต่มันคือสิ่งที่ทำให้ Bug 2 มองไม่เห็นจากข้างใน: `this.store[key] = value` ไม่เคยบ่นไม่ว่าจะมีอะไรถูก assign จริง เพราะ `any` รับทุกอย่างแบบเงียบ ๆ

**Fix:** container ที่เป็น generic จริง — `Map<string, T>` — เก็บ `T` แม่นยำตลอดสาย:

```ts
// @skip-verify partial snippet, illustrates the fix only -- see the full fixed version below
class DataCache<T> {
  private store: Map<string, T> = new Map();
  set(key: string, value: T): void {
    this.store.set(key, value);
  }
  get(key: string): T | undefined {
    return this.store.get(key);
  }
}
```

</details>

<details>
<summary>Bug 2 — บรรทัด 24, `seedWithCat(dogCache)`</summary>

**Symptom:** `dogCache` เป็น `DataCache<Dog>`; `seedWithCat` คาดหวัง `DataCache<Animal>` TypeScript ยอมให้ assign ได้ เพราะ `set(key: string, value: T): void` เขียนด้วย **method-shorthand syntax** ซึ่งถูกตรวจแบบ bivariant — ช่องเดียวกันเป๊ะกับที่บท variance ของคอร์สนี้แสดงบน `Stack<T>` ที่เขียนเอง

**Evidence:** การ crash จริง `seedWithCat` push `Cat` เข้าไปในสิ่งที่ข้างใต้คือ `dogCache` เอง; `dogCache.get("pet")` ทีหลังคืน `Cat` นั้น type เป็น `Dog` แล้ว `.bark()` ก็ throw

**Fix:** ถ้า function แค่ต้องการ *อ่าน* จาก generic container ให้รับ type ที่ mutate ผ่านไม่ได้ — ตรงนี้คือ `ReadonlyMap<string, Animal>` — เพื่อไม่ให้มี `set` ให้ใช้ประโยชน์ตั้งแต่แรก:

```ts
// @skip-verify partial snippet, illustrates the fix only -- see the full fixed version below
function describeAnimals(cache: ReadonlyMap<string, Animal>): void {
  for (const animal of cache.values()) console.log(animal.speak());
}
```

</details>

<details>
<summary>Bug 3 — บรรทัด 26, `interface Repository<T>` ที่มี implementer เดียว</summary>

**Symptom:** `Repository<T>` ถูก implement โดย class เดียวตลอดกาล และ `T` โผล่แค่ตำแหน่งเดียว (return type ของ `findById`) มันเพิ่ม declaration ตัวที่สองที่ผู้อ่านต้องเปิดเพื่อเข้าใจ `UserCacheRepository` โดยไม่ได้ polymorphism อะไรจริงเลย

**Evidence:** ไม่มี crash ไม่มี diagnostic — ต้นทุนเป็นเชิงโครงสร้างล้วน ๆ ไม่มีอะไรในโปรแกรมนี้เคยรับ `Repository<T>` ที่ `UserCacheRepository` แบบ concrete ทำหน้าที่แทนไม่ได้ดีเท่ากันเลย

**Fix:** ลบ interface ทิ้ง เก็บแค่ class ที่ concrete

</details>

<details>
<summary>Bug 4 — บรรทัด 45, `persistToRemote(entry);` ไม่มี `await`</summary>

**Symptom:** call ที่ persist ไปยัง remote ถูกยิงแล้วลืม `cacheAndPersist` return ทันที ก่อนที่ `persistToRemote` จะทำอะไรที่สังเกตได้เลย

**Evidence:** `persisted: Ada` ไม่เคยพิมพ์ใน real output — process crash ที่ bug variance ของ cache ที่ไม่เกี่ยวข้องกันก่อนที่ timer 5ms ที่ถูกทิ้งไว้จะมีโอกาสยิง

**Fix:** `await` มัน แล้วทำให้ `cacheAndPersist` เองเป็น `async`:

```ts
// @skip-verify partial snippet, illustrates the fix only -- see the full fixed version below
async function cacheAndPersist(repo: UserRepository, entry: UserRecord): Promise<void> {
  repo.save(entry.id, entry);
  await persistToRemote(entry);
}
```

</details>

## Version ที่แก้แล้ว

```ts
// @run
interface UserRecord { id: number; name: string }

class DataCache<T> {
  private store: Map<string, T> = new Map();
  set(key: string, value: T): void {
    this.store.set(key, value);
  }
  get(key: string): T | undefined {
    return this.store.get(key);
  }
}

class Animal { speak(): string { return "..."; } }
class Dog extends Animal { bark(): string { return "woof"; } }
class Cat extends Animal { speak(): string { return "meow"; } }

function describeAnimals(cache: ReadonlyMap<string, Animal>): void {
  for (const animal of cache.values()) console.log(animal.speak());
}

const dogCache = new DataCache<Dog>();
dogCache.set("pet", new Dog());
// describeAnimals only reads, and only accepts a read-only view -- no way to sneak a Cat in

class UserRepository {
  private cache = new DataCache<UserRecord>();
  save(id: number, record: UserRecord): void {
    this.cache.set(String(id), record);
  }
  findById(id: number): UserRecord | undefined {
    return this.cache.get(String(id));
  }
}

async function persistToRemote(entry: UserRecord): Promise<void> {
  await new Promise<void>((resolve) => setTimeout(resolve, 5));
  console.log("persisted:", entry.name);
}

async function cacheAndPersist(repo: UserRepository, entry: UserRecord): Promise<void> {
  repo.save(entry.id, entry);
  await persistToRemote(entry);
}

async function main(): Promise<void> {
  const repo = new UserRepository();
  await cacheAndPersist(repo, { id: 1, name: "Ada" });
  console.log(repo.findById(1));

  const pet = dogCache.get("pet");
  console.log(pet?.bark());
}

main();
```

**Real output:**

```text
persisted: Ada
{ id: 1, name: 'Ada' }
woof
```

ทุกบรรทัดรันตามลำดับ `persisted: Ada` พิมพ์ก่อนที่อะไรจะมารออีก และ `dogCache` ยังเก็บ `Dog` จริงอยู่ — ไม่มีทางแอบใส่ `Cat` เข้าไปได้เลย

## เครื่องมือจับอะไรได้บ้าง

`tsc --strict`: **ไม่มี error เลย** ทั้งสอง version

typed rule ของ `typescript-eslint` รันกับ version ที่มี bug:

```text
4:33   error  Unexpected any. Specify a different type              @typescript-eslint/no-explicit-any
9:5    error  Unsafe return of a value of type `any`                 @typescript-eslint/no-unsafe-return
46:3   error  Promises must be awaited, end with a call to .catch, end with a call to .then
               with a rejection handler or be explicitly marked as ignored with the `void`
               operator                                               @typescript-eslint/no-floating-promises

✖ 3 problems (3 errors, 0 warnings)
```

Bug 1 (`any`) กับ Bug 4 (floating promise) ถูกจับโดยตรง Bug 2 กับ 3 ไม่ถูกจับ: ช่อง variance เป็น unsoundness แบบตั้งใจและมี document ไว้เดียวกับที่บท [Generic Classes & Interfaces](/typescript/th/generics/generic-classes-and-interfaces/) ของคอร์สนี้แสดงไว้ และไม่มี lint rule ไหนตรวจว่า generic interface คุ้มกับ abstraction ที่ใส่ไปหรือเปล่า — มีแค่รายงาน unused-exports ของ `knip` ที่รันบนโปรเจกต์จริงหลายไฟล์เท่านั้นที่จะบอกใบ้ Bug 3 ได้ โดยแสดงว่า `Repository` ถูกอ้างถึงจากที่เดียว

<Callout title="สรุปหนึ่งบรรทัด">
`any` ข้างใน cache กับ `await` ที่หายไป ห่างจากการเจอแค่ `eslint --fix` ระดับหนึ่ง; ช่อง variance กับ generic interface ที่ไม่จำเป็นทั้งคู่ compile ผ่านสะอาดและต้องให้คนที่อ่านบท variance ของคอร์สนี้มาแล้วถึงจะเห็นมันได้เลย
</Callout>
