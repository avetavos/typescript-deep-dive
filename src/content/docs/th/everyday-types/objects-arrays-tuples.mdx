## object type และ modifier ของตัวเอง

object type อธิบาย shape ด้วยการ list property modifier สองตัวสื่อความหมายเยอะ:

```ts
interface User {
  readonly id: string;   // reassign ไม่ได้หลังสร้าง
  name: string;          // required
  email?: string;        // optional — string | undefined
}
```

- **`readonly`** บล็อกการ reassign property เป็น compile-time เท่านั้น (runtime ไม่ได้กันการ mutate) แต่สื่อและ enforce เจตนา
- **`?` (optional)** หมายถึง property อาจไม่มี สำคัญคือ optional property มี type `T | undefined` คุณจึงต้อง handle case `undefined`:

```ts
function greet(u: User) {
  u.email.toLowerCase();
  // ❌ Object is possibly 'undefined'.
  u.email?.toLowerCase(); // ✅ optional chaining จัดการกรณีไม่มี
}
```

`interface` กับ `type` แทบใช้แทนกันได้สำหรับ object shape; `interface` เปิดต่อได้ (declaration merging) และ idiomatic สำหรับ public object contract ส่วน `type` ยังเขียน union, tuple และ mapped type ได้ ใช้ `type` เมื่อต้องการพวกนั้น สำหรับ object ธรรมดาใช้อันไหนก็ได้

## index signature: object เป็น map

เมื่อยังไม่รู้ key ล่วงหน้า **index signature** type ทุก key แบบ uniform:

```ts
interface Scores {
  [player: string]: number;
}

const s: Scores = { ada: 10, alan: 12 };
s.grace = 9; // ✅ key เป็น string ใด ๆ, value เป็น number
```

ราคาที่ต้องจ่ายคือความซื่อสัตย์เรื่องการไม่มีค่า: `s.someone` มี type `number` แต่จริง ๆ เป็น `undefined` ตอน runtime ด้วย option `noUncheckedIndexedAccess` TypeScript จะทำให้เรื่องนี้เป็นจริง โดย type ทุก index access เป็น `number | undefined` — เป็น setting ที่แนะนำอย่างยิ่ง

## array เทียบ tuple

**array** คือ list ที่ homogeneous และยาวเท่าไรก็ได้: `number[]` คือ "number กี่ตัวก็ได้" **tuple** คือ list ความยาวคงที่ที่แต่ละตำแหน่งมี type ของตัวเอง:

```ts
let list: number[] = [1, 2, 3, 4];         // ยาวเท่าไรก็ได้ เป็น number หมด
let point: [number, number] = [10, 20];    // number สองตัวพอดี
let pair: [string, number] = ["age", 36];  // ตำแหน่ง 0 string, ตำแหน่ง 1 number
```

tuple ขับเคลื่อน pattern อย่าง return ของ `useState` ใน React (`[value, setter]`) และพิกัดแบบมีชื่อกลาย ๆ tuple ยังรองรับ **label** (เป็น documentation ไม่มีผล runtime) และ rest element:

```ts
type HttpResult = [status: number, body: string];
type Args = [first: string, ...rest: number[]];
```

## `readonly` array และ tuple

`readonly number[]` (หรือ `ReadonlyArray<number>`) ห้าม method ที่ mutate อย่าง `push` และการ assign ที่ index — เหมาะกับ parameter ที่คุณสัญญาว่าจะไม่แก้ และจำจากบทที่แล้ว: `as const` บน array literal ให้ `readonly` tuple ของ literal พอดี:

```ts
const rgb = [255, 128, 0] as const;
// type: readonly [255, 128, 0]

function paint(color: readonly number[]) { /* mutate color ไม่ได้ */ }
```

การเลือกใช้ `readonly` array parameter เป็นนิสัยราคาถูกที่ได้ค่ามาก: กันบั๊ก mutate โดยไม่ตั้งใจทั้งชุด และสื่อเรื่อง ownership

## built-in ใหม่ ๆ ที่ `lib` ใส่ type ให้แล้ว (es2024 / es2025)

เมื่อ `target` และ `lib` เป็น `es2025` (ค่าเริ่มต้นของ TypeScript 7) โค้ดจัดการ collection หลายอย่างที่เคยต้องพึ่ง helper library ก็มี type มาให้ทันที:

- **Set algebra (5.5):** `a.union(b)`, `intersection`, `difference`, `symmetricDifference`, `isSubsetOf`, `isSupersetOf`, `isDisjointFrom` — ทุกตัว return `Set` ที่ type ถูกต้อง
- **Iterator helper (5.6):** generator และ built-in iterator มี `.map`, `.filter`, `.take`, `.drop`, `.flatMap`, `.reduce`, `.toArray` และ `Iterator.from(...)` type ของมันคือ `IteratorObject<T>` (และ `AsyncIteratorObject<T>`) แยกจาก interface `Iterator` ที่คุณ implement เอง:

  ```ts
  function* naturals() { let i = 1; while (true) yield i++; }
  const evens = naturals().map((n) => n * 2).take(3).toArray(); // number[]

  const byEmail = new Map(userById.entries().map(([id, u]) => [u.email, id]));
  ```

- **grouping (es2024):** `Object.groupBy(items, (x) => x.kind)` return `Partial<Record<K, T[]>>`; `Map.groupBy` return `Map`
- **upsert (6.0):** `map.getOrInsert(key, fallback)` และ `map.getOrInsertComputed(key, () => …)`
- **อยู่ใน `es2025` ด้วย:** `RegExp.escape`, `Promise.try`, `Promise.withResolvers` และ type ของ **Temporal** ในตัว (`Temporal.Now.instant()`) ไม่ต้องลง `@types` เพิ่มแล้ว

## typed array เป็น generic แล้ว (5.7 / 5.9)

`Uint8Array` และพวกพ้องกลายเป็น generic เหนือ buffer ของมัน — `Uint8Array<TArrayBuffer extends ArrayBufferLike = ArrayBufferLike>` — และใน 5.9 `ArrayBuffer` เลิกเป็น supertype ของ typed array ผลในทางปฏิบัติ: API ที่ต้องการ `BufferSource` จะปฏิเสธค่าที่มี type `ArrayBufferLike` และ `Buffer` ของ Node assign ให้ `Uint8Array<ArrayBuffer>` ไม่ได้อีก แก้ด้วยการระบุ type ของ buffer หรือส่ง `.buffer`:

```ts
const data = new Uint8Array([1, 2, 3]);      // Uint8Array<ArrayBuffer>
send(data.buffer);                            // ✅ ArrayBuffer
function send(b: Uint8Array<ArrayBuffer>) {}  // ระบุให้ชัดเมื่อคุณเป็นเจ้าของ API
```

## `using`: cleanup resource ตาม scope (5.2)

Explicit Resource Management — `using` และ `await using` — มาใน TypeScript 5.2 และตอนนี้ Node.js 24+ กับ browser สมัยใหม่รันได้ native ค่าที่มี `[Symbol.dispose]` (หรือ `[Symbol.asyncDispose]`) จะถูก cleanup เมื่อออกจาก block ในลำดับย้อนกลับ แม้จะ `throw`:

```ts
function openFile(path: string) {
  const fd = fs.openSync(path, "r");
  return { fd, [Symbol.dispose]() { fs.closeSync(fd); } };
}

function read() {
  using file = openFile("data.txt"); // ปิดให้อัตโนมัติเมื่อจบ block
  return fs.readFileSync(file.fd);
}
```

`Disposable` และ `AsyncDisposable` คือ interface ที่ต้อง implement ส่วน `DisposableStack` รวมหลายตัวไว้ด้วยกัน model resource แบบนี้แทนบันได `try`/`finally`
