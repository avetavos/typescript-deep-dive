## default เปลี่ยนไปใน TypeScript 6

ตลอดสิบปี `tsconfig.json` ที่ว่างเปล่าแปลว่า compiler แบบ *หลวม*: ไม่มี `strict`, output เป็น CommonJS, ES target เก่า และ package `@types/*` ทุกตัวใน `node_modules` ถูกโหลดเงียบ ๆ TypeScript 6.0 (มีนาคม 2026) พลิก default ให้เป็นสิ่งที่แทบทุกโปรเจกต์เขียนเองอยู่แล้ว และ TypeScript 7.0 (กรกฎาคม 2026, native compiler) ทำให้มันเป็นของถาวร:

| Option | ก่อน 6.0 | default ใน 6.0 / 7.0 |
|--------|------------|-------------------|
| `strict` | `false` | `true` |
| `module` | `commonjs` | `esnext` |
| `target` | ประมาณ `es2020` | `es2025` — ขยับตาม ECMAScript ของปีปัจจุบัน |
| `types` | `@types/*` ทุกตัวใน `node_modules` | `[]` — ไม่โหลดอะไรเลยนอกจากที่คุณระบุ |
| `rootDir` | infer จาก source ของคุณ | `.` — directory ของ `tsconfig.json` |
| `noUncheckedSideEffectImports` | `false` | `true` |
| `libReplacement` | `true` | `false` |

สองตัวในนี้กัดโปรเจกต์จริงตอน upgrade `types: []` แปลว่า `@types/node` ไม่ถูกหยิบมาใช้แค่เพราะ install ไว้ — ต้องเขียน `"types": ["node"]` (หรือ `["*"]` ถ้าอยากได้พฤติกรรมเดิม) ส่วน `rootDir: "."` แปลว่า layout แบบ `src/` จะ emit ไปที่ `dist/src/` ถ้าไม่ตั้ง `"rootDir": "./src"` ให้ชัด — และเรื่องนี้ไม่เงียบ: ถ้าตั้ง `outDir` ไว้แต่ปล่อย `rootDir` เป็น default `tsc` จะหยุดด้วย hard error **และยังเขียนไฟล์ไปที่ path ที่ซ้อนอยู่ดี**:

```
error TS5011: The common source directory of 'tsconfig.json' is './src'. The 'rootDir' setting must
be explicitly set to this or another path to adjust your output's file layout.
```

## `tsc --init` เขียนอะไรให้ตอนนี้

`tsc --init` generate ไฟล์สั้น ๆ ที่มีความเห็นชัดเจน แทนกำแพง option ที่ comment ไว้ นี่คือ output จริงของ `tsc --init` บน TypeScript 7.0.2 (ตัด comment ยาวบางส่วนออก แต่บรรทัด `rootDir`/`outDir` ที่ถูก comment ไว้คือของจริงเป๊ะ):

```json
{
  // Visit https://aka.ms/tsconfig to read more about this file
  "compilerOptions": {
    // File Layout
    // "rootDir": "./src",
    // "outDir": "./dist",

    // Environment Settings
    // See also https://aka.ms/tsconfig/module
    "module": "nodenext",
    "target": "esnext",
    "types": [],
    // For nodejs:
    // "lib": ["esnext"],
    // "types": ["node"],
    // and npm install -D @types/node

    // Other Outputs
    "sourceMap": true,
    "declaration": true,
    "declarationMap": true,

    // Stricter Typechecking Options
    "noUncheckedIndexedAccess": true,
    "exactOptionalPropertyTypes": true,

    // Style Options
    // "noImplicitReturns": true,
    // "noImplicitOverride": true,
    // "noUnusedLocals": true,
    // "noUnusedParameters": true,
    // "noFallthroughCasesInSwitch": true,
    // "noPropertyAccessFromIndexSignature": true,

    // Recommended Options
    "strict": true,
    "jsx": "react-jsx",
    "verbatimModuleSyntax": true,
    "isolatedModules": true,
    "noUncheckedSideEffectImports": true,
    "moduleDetection": "force",
    "skipLibCheck": true,
  }
}
```

สังเกตว่า `rootDir` กับ `outDir` ถูก generate มาแบบ **comment ทิ้งไว้** — `tsc --init` ให้เห็น shape แต่ไม่เดา layout ให้ ซึ่งก็คือ gotcha ของ `rootDir` ที่คุยไว้ข้างบนพอดี `verbatimModuleSyntax` กับ `isolatedModules` อธิบายอยู่ใน [Build & Emit](/typescript/th/compiler-and-tooling/build-and-emit/); หลายบรรทัดในนี้ซ้ำกับ default อยู่แล้ว (`strict`, `noUncheckedSideEffectImports`) — generator ตั้งใจเขียนให้ชัดเพื่อให้ไฟล์อธิบายตัวเองได้

## `strict` เปิดอะไรให้จริง ๆ

`strict` เป็น default แล้ว แต่ก็ยังควรรู้ว่ามันรวมอะไรไว้ เพราะคุณจะเจอ codebase ที่ปิดบางส่วนของมันไป:

| Flag (อยู่ใน `strict`) | สิ่งที่จับได้ |
|------------------------|-----------------|
| `strictNullChecks` | `null` และ `undefined` ไม่แอบอยู่ในทุก type อีกต่อไป — คุ้มที่สุด |
| `noImplicitAny` | value ที่จะ fall back เป็น `any` กลายเป็น error ที่คุณต้องแก้ |
| `strictFunctionTypes` | parameter ของ function ถูก check แบบ contravariant — callback ที่ไม่ปลอดภัยถูกจับ |
| `strictBindCallApply` | `bind`, `call` และ `apply` ถูก type-check กับ signature ของ function |
| `strictPropertyInitialization` | field ของ class ต้องถูก assign ใน constructor (หรือ mark เป็น optional) |
| `useUnknownInCatchVariables` | `catch (e)` ให้ `unknown` ไม่ใช่ `any` บังคับให้คุณ narrow |
| `strictBuiltinIteratorReturn` | iterator built-in return `undefined` ตอนจบ ไม่ใช่ `any` (5.6) |
| `noImplicitThis` | `this` ที่จะ fall back เป็น `any` (เช่นใน plain function ที่ใช้เป็น method) กลายเป็น error |
| `alwaysStrict` | parse ใน strict mode และ emit `"use strict"` — ปิดไม่ได้อีกแล้ว |

พระเอกคือ `strictNullChecks` ถ้าไม่เปิด `string` จะแอบรวม `null` และ `undefined` ไว้ด้วย และ compiler เตือนคุณเรื่อง runtime crash ที่พบบ่อยที่สุดใน JavaScript ไม่ได้เลย พอเปิดแล้ว `null` และ `undefined` กลายเป็น type ของตัวเองที่คุณต้องจัดการอย่างตั้งใจ

ถ้าคุณรับช่วงโปรเจกต์ที่มี `"strict": false` ให้มองเป็นงาน migration (ดู [Migration Strategy](/typescript/th/practical-mastery/migration-strategy/)) — เปิด flag ทีละตัว อย่าลบบรรทัดนั้นทิ้งแล้วจมอยู่กับ error

## `target`, `module` และ `lib`

สาม option นี้อธิบายโลกที่ code ของคุณรันอยู่:

- **`target`** — JavaScript version ที่ `tsc` emit ออกมา default `es2025` (และ `esnext`) แปลว่า *ไม่ down-level*: syntax สมัยใหม่ถูกส่งผ่านไปตรง ๆ ซึ่งเป็นสิ่งที่ runtime ปัจจุบันทุกตัวต้องการ target ที่ต่ำกว่ายัง down-level syntax ใหม่ ๆ ได้ — แต่ `es5` หายไปแล้ว (เป็น hard error ใน 7.0; ES2015 คือพื้น) และ `downlevelIteration` ก็หายไปด้วย
- **`module`** — module format ของ output ใช้ `nodenext` เมื่อ Node รัน output โดยตรง, `esnext` หรือ `preserve` เมื่อ bundler เป็นคนจัดการ และ `node18` / `node20` แบบ stable เมื่ออยาก pin พฤติกรรมไว้กับ Node สายใดสายหนึ่ง บทถัดไปลงลึกเรื่องนี้
- **`lib`** — type declaration built-in ตัวไหนที่ใช้ได้ ตอนนี้ `lib.dom` รวมสิ่งที่เคยอยู่ใน `dom.iterable` และ `dom.asynciterable` ไว้แล้ว; `es2025` เพิ่ม `RegExp.escape`, helper method ของ `Iterator`, method พีชคณิตของ `Set` และ method upsert ของ `Map` (`getOrInsert`, `getOrInsertComputed`) และ type ของ `Temporal` มาพร้อม 6.0 ถ้าคุณใช้ API แล้วเจอ "does not exist" แปลว่า `lib` ของคุณเก่าเกินไป

## flag ข้าง ๆ strict ที่ควรเพิ่ม

`strict` เป็นพื้น ไม่ใช่เพดาน อีกสอง flag จับ bug ที่ `strict` อย่างเดียวพลาด:

```ts
// noUncheckedIndexedAccess: true
const arr = [1, 2, 3];
const x = arr[10]; // type is now `number | undefined`, not `number`
x.toFixed(); // ❌ Object is possibly 'undefined' — exactly the bug you want caught
```

- **`noUncheckedIndexedAccess`** — การ index array หรือ record อาจ return `undefined` ได้ (index 10 ของ array 3 ตัวก็ return) type จึงสะท้อนความจริงนั้น มีประสิทธิภาพมากในการกัน bug out-of-bounds
- **`exactOptionalPropertyTypes`** — แยกความต่างระหว่าง property ที่ set เป็น `undefined` กับ property ที่หายไปเลย ทำให้ optional `name?: string` ไม่แอบรับ `name: undefined` อีกต่อไป
- **`noUncheckedSideEffectImports`** (default ตั้งแต่ 6.0) — เมื่อก่อน `import "./styles.css"` ที่ path ผิดจะ resolve เป็นความว่างเปล่าเงียบ ๆ ตอนนี้พิมพ์ผิดคือ error ประกาศ `declare module "*.css" {}` ครั้งเดียวสำหรับ asset import ที่ bundler จัดการให้
- **`erasableSyntaxOnly`** (5.8) — ห้าม syntax ของ TypeScript ที่ต้อง *transform* ไม่ใช่แค่ *ลบ*: `enum`, `namespace` ที่มี runtime code, parameter property ใน class, `import x = require()` เปิดไว้ถ้าคุณรันไฟล์ `.ts` ตรง ๆ ใน Node (type stripping), Deno หรือ Bun ที่ runtime แค่ strip type ออก

## option ที่ถูกถอดออก และอะไรมาแทน

TypeScript 6.0 deprecate option ชุดหนึ่ง และ 7.0 ถอดออกไปเลย ใน 6.x ซื้อเวลาได้ด้วย `"ignoreDeprecations": "6.0"` แต่ทุกตัวมีของแทนตรง ๆ:

| ถูกถอด | แทนด้วย |
|---------|--------------|
| `baseUrl` | ยุบ prefix เข้าไปใน `paths`: `"@app/*": ["./src/app/*"]` |
| `moduleResolution: node` / `node10` / `classic` | `nodenext` (Node รัน) หรือ `bundler` (bundler จัดการ) |
| `module: amd` / `umd` / `system` / `none` | `esnext` หรือ `preserve` แล้วให้ bundler ผลิต format อื่น |
| `outFile` | bundler |
| `target: es5`, `downlevelIteration` | `es2015` หรือใหม่กว่า |
| `esModuleInterop: false`, `allowSyntheticDefaultImports: false`, `alwaysStrict: false` | ไม่ต้องทำอะไร — เปิดตลอดเวลาแล้ว |
| `import x from "./data.json" asserts { type: "json" }` | `with { type: "json" }` |
| `module Foo {}` (keyword namespace แบบเก่า) | `namespace Foo {}` |
| `/// <reference no-default-lib="true" />` | `noLib` หรือ `libReplacement` |

มีการเปลี่ยน CLI อีกเรื่องที่อยู่ตรงนี้ด้วย: การรัน `tsc file.ts` ใน directory ที่มี `tsconfig.json` ตอนนี้เป็น error (TS5112) เพราะมันแอบ ignore config มาหลายปี ใส่ `--ignoreConfig` ถ้าตั้งใจแบบนั้นจริง ๆ

## option เล็ก ๆ ที่คุณจะได้ใช้จริง

- **`${configDir}`** (5.5) — template variable สำหรับ path ใน base config ที่ share กัน ทำให้ `"outDir": "${configDir}/dist"` resolve เทียบกับโปรเจกต์ที่ *extend* ไม่ใช่ไฟล์ base
- **`noCheck`** (5.6) — emit โดยไม่ type-check เป็นภาพสะท้อนของ `noEmit` มีประโยชน์เมื่อ step อื่นเป็นคน check
- **`isolatedDeclarations`** (5.5) — บังคับ type ชัดเจนบน export เพื่อให้ผลิต `.d.ts` ทีละไฟล์แบบขนานได้โดยไม่ต้องใช้ checker
- **`rewriteRelativeImportExtensions`** (5.7) — ให้คุณเขียน `import "./util.ts"` แล้ว `tsc` emit เป็น `./util.js`
- **`libReplacement`** (5.8) — opt in ให้แทน `lib.dom` ด้วย npm package เช่น `@typescript/lib-dom`; ปิดเป็น default ตั้งแต่ 6.0
- **`skipLibCheck`** — ข้ามการ check ไฟล์ `.d.ts` ใน `node_modules` ยังเป็นการเร่งความเร็วที่ถูกที่สุดตัวเดียว แม้บน native compiler

<Callout title="สรุปหนึ่งบรรทัด">
TypeScript 6/7 default เป็น `strict`, `module: esnext`, `target` ของปีปัจจุบัน, `types: []` และ `rootDir: "."` — ดังนั้นตั้ง `types` กับ `rootDir` ให้ชัด และใช้ config สั้น ๆ จาก `tsc --init` เป็น template `strictNullChecks` ยังเป็น check ที่สำคัญที่สุด เพิ่ม `noUncheckedIndexedAccess` กับ `exactOptionalPropertyTypes` ทับลงไป และแทน option ที่ถูกถอด (`baseUrl`, `moduleResolution: node`, `outFile`, `es5`) ด้วย `paths`, `nodenext`/`bundler`, bundler และ target สมัยใหม่
</Callout>
